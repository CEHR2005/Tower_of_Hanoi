# Исследование и выбор алгоритма

Исследование выполнено 2026-10-08 **до реализации**. Рассматриваются только
три стержня, перенос A → C, все диски изначально на A. Число 0 означает пустую
башню. Здесь и далее диски нумеруются от 1 (наименьший), стержни — 0, 1, 2.

## Оптимальность и нижняя граница

Ниже — самостоятельное изложение классического индуктивного доказательства,
согласующееся с рекурсией из [1]. Пусть T(N) — минимальная длина переноса
полной башни между различными стержнями, T(0)=0.
Перед **первым** перемещением наибольшего диска все N−1 меньших должны
оказаться на одном другом стержне: требуется не менее T(N−1) ходов.
После **последнего** перемещения наибольшего диска на C меньшие диски опять
собраны на третьем стержне и требуют не менее T(N−1) ходов до цели.
Эти участки не пересекаются; между ними есть хотя бы один ход наибольшего.
Поэтому T(N) ≥ 2T(N−1)+1. Рекурсивный перенос меньшей башни A→B, большого
A→C и меньшей B→C достигает границы: T(N)=2^N−1.
Это доказательство допускает и исключает выигрыш от повторных ходов большого
диска, а не предполагает заранее, что он движется только один раз.

Явная выдача M=2^N−1 ходов требует Ω(M) операций даже без терминала.
Все рассматриваемые генераторы имеют Θ(M) полное время. Вычисление **числа**
ходов в одном машинном слове имеет O(1) время и не является решением задачи
генерации. Для неограниченного N число содержит N бит; утверждение O(1)
больше неприменимо. Реализация намеренно ограничена N≤64 и uint64_t.

## Биты, код Грея и направление

У отражённого кода Грея g(m)=m XOR (m>>1) между g(m−1) и g(m) меняется бит
k=ctz(m). Рекурсивная последовательность дисков —
1,2,1,3,1,2,1,4,…; по индукции её m-й элемент d=ctz(m)+1.
Диск d движется каждый 2^d-й шаг начиная с 2^(d−1).
До шага m он сделал q=floor(m/2^d) перемещений.
Направление s равно +1 при нечётном N+d, иначе −1 (или +2 modulo 3).
Это правило следует индукцией из обмена вспомогательного и целевого стержней
при переходе к подзадаче; также см. Proposition 1 в [1]. Поэтому
источник = s·q mod 3, приёмник = s·(q+1) mod 3.
Реализация q=(m>>1)>>ctz(m) избегает сдвига на 64 при d=64.
Это кандидат `formula`: один остаток q%3 и несколько малых операций.

Альтернативный кандидат `bitwise`:

```
x = m & (m-1)
y = m | (m-1)
from = x % 3
to = (y % 3 + 1) % 3
```

Для нечётного N это непосредственно A,B,C; для чётного меняются B и C.
Обоснование: m=(2q+1)·2^k, x=q·2^(k+1), y+1=(q+1)·2^(k+1).
Поскольку 2 ≡ −1 (mod 3), получаются те же направления, что выше.
В коде нельзя буквально вычислять y+1: при последнем ходе N=64 оно равно
2^64. Сначала берётся y%3, затем прибавляется 1 с условным вычитанием 3.
Счётчик цикла также не должен увеличиваться после UINT64_MAX.

## Сравнение до измерений

Количество операций ниже — описание исходного алгоритма, **не** количество
машинных инструкций или тактов. Остаток от деления на константу компилятор
может заменить умножением и сдвигами. Все варианты потоковые, без массива M ходов.

| Подход | Полное время | Управляющая память | Работа на ход и накладные расходы |
|---|---|---|---|
| Классическая рекурсия | Θ(M) | O(N) стек | вызовы/возвраты, проверки базового случая; амортизированно O(1), задержка между ходами до O(N) |
| Явный стек рекурсивных кадров | Θ(M) | O(N) | push/pop, стадии кадров; не обещает выигрыша относительно вызовов |
| Итерация `iterative` с позициями дисков | Θ(M), инициализация O(N) | O(N) | ctz, чтение/запись позиции, направление по чётности, приведение малого значения modulo 3 |
| Loopless с вершинами стержней [1] | Θ(M) | O(N) состояние | чередование малого диска и единственного допустимого другого хода, сравнение вершин |
| Битовые маски FXT [4] | Θ(M) при N в слове | O(1) слов | выделение lowbit, поиск среди 3 масок, XOR и циклический индекс; демо включает вывод |
| `bitwise` | Θ(M) | O(1) слов | ctz для номера диска, AND, OR, два 64-битных %3, отображение стержней |
| `formula` | Θ(M) | O(1) слов | ctz, два сдвига, один 64-битный %3, выбор направления и малые коррекции |

O(1) здесь относится к управляющей памяти в модели фиксированного машинного
слова для N≤64; физическая визуализация хранит O(N) дисков. При произвольном
N стоимость больших целых и память растут. Отсутствие рекурсии доказуемо
убирает стек, но **не доказывает превосходство по скорости**.

## Решение до реализации

Предварительный основной вариант — `formula`: O(1) управляющей памяти,
прямое доказательство через расписание дисков, один большой остаток на ход.
Его выбор должен быть проверен измерениями против `recursive`, `iterative`
и `bitwise`; окончательное решение и отклонённые оптимизации — в benchmarks.md.
Не заявляется мировой рекорд или превосходство над всеми loopless-реализациями.

Ядро — заголовочный C++20 API с шаблонным получателем хода; выбор алгоритма
один раз до цикла. CLI отдельно от ASCII/ANSI-рендера. В быстром режиме
получатель обновляет контрольную сумму, без хранения конфигурации или вызова
рендера. Бенчмарк использует одинаковый получатель и отдельный процесс для
каждого замера RSS. Сторонние библиотеки не нужны.

Охват реализации: ядро и его публичные проверки, CLI, визуализация, тесты
состояний и команд, бенчмарк/скрипт измерений, CMake, Docker, документация.
Каталог изначально пуст: существующих вызывающих функций и данных нет.
